## Expiry

New positive-total COD checkout stores orders.confirmation_expires_at=ClockUTC+configured86400seconds. User chose24hours; environment override ORDER_CONFIRMATION_TTL_SECONDS, validated60..604800. Existing orders NULL remain unexpired; zero orders and BANK_TRANSFER have no automatic deadline. A new bank retry clears an old COD deadline. Confirmation to CONFIRMED clears it too. Mixed/unknown/gateway/manual-bank rows are skipped. No fake staff/user0. Same order root serializes payment confirmation/dispatch/expiry; late actual manual collection still queues durable refund via existing service. Failure rolls back all effects and leaves hold intact; durable expiry_attempts/expiry_retry_after backoff prevents a poison due row starving the scan. Scheduler defaultenabled, global COMMERCE_JOBS_ENABLED false for tests; manual staff trigger does same eligibility, no force/backdate override.
